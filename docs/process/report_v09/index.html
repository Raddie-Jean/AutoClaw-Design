AutoClaw Design Agent 工作区｜方案汇报 V09

汇报结论：本题的重点不是让 Agent 再多生成一种网页，而是让设计师把已经生成的 HTML 初稿变成一份可定位修订、可阶段评审、可固定版本交付的设计成果。建议沿用 AutoClaw 的项目与任务外壳，在一次 Design 任务内增加“成果总览 → 聚焦预览 → 修订审阅 → 阶段评审 → 交付快照”。开放题只深入一个 Feature：界面定域修订。

本稿配套 01_封面.svg—12_验证计划.svg，每页为 1600 × 900 独立 SVG。它们是汇报画面，支持逐页导入 Figma 后继续改动。当前的 可点击原型 用“邀请成员流程”演示主链路。原型中的 AI 修改为交互模拟，不是已实现的 AutoClaw 功能。

1. 思路如何收敛

阶段 得到的判断 对本次方案的影响
V01–V02：设计 AI 工具与产物调研 生成方式、格式、画布和导出方式很多；仅把结果转成另一种格式，不能保证可编辑或可开发。 选择可运行 HTML 项目作为本题的主产物，不承诺任意格式无损转换。
V03：AutoClaw / Lovart 录屏与 MVP AutoClaw 的任务与产物外壳可承接 Design 结果；Lovart 的对象选择、局部指令和旁置候选可迁移为设计交互模式。 不新增全局设计软件首页；在现有任务内组织持续演化的产物。
V04–V05：旅程、信息架构与多方共创 设计师需要看清初稿、控制修改，PM 与开发需要在不同时间回答不同问题。 把草图概念评审、Demo 体验评审和开发接手拆开。
V06：草图三态 草图收集应保留不确定性；定义概念时可同时深化 1–3 个方向；确定概念后才进入运行体验判断。 G1 概念确认后移到草图第三态末尾。
V07–V08：界面定域修订与原型 重写整段提示词容易丢失已接受部分；局部修改需要目标、范围、候选、对比和人的决定。 聚焦一条从初稿到固定交付的主链路，做成可点击原型。

舍弃或后置：无限画布全功能、任意 HTML↔Figma 无损双向同步、任意图片/视频统一精准编辑、自动把 Demo 代码合并到生产仓库。这些能力可能有价值，但不能替代对主链路的验证。

2. 证据、推论和待验证项

直接观察：用户提供的 AutoClaw 录屏呈现首页、任务、项目、对话与连接器等通用外壳；一次客户端只读走查还看到“输出产物”与浏览器/文件工作区容器。该录屏中的任务是图片生成，不是 HTML Design 任务。用户提供的 Lovart 录屏呈现选中素材对象、Quick Edit、原稿旁生成候选与对象下载；它证明对象化局部编辑是可理解的交互范式，不能证明 HTML 源码能同样精准回写。详细截图见 MVP 观察记录。

外部研究提示：Figma 针对 906 位数字设计师的 2026 调查显示，创作自主权和明确目标与预期受到重视；一项 24 人 GenUI 研究指出多屏方向的预览困难；Figma 2025 设计师/开发者报告提示双方频繁协作且存在假设差异。这些结果支持“保留判断权、清晰预览、传递意图”的方向，不代表 AutoClaw 用户痛点发生率。研究范围与口径见 用户旅程 V04。

本次产品假设：一次 HTML Design 任务结束后，最影响后续工作的三个断点按顺序为：①看不全页面/状态；②无法确定 AI 修改的实际目标与影响；③PM/开发难以确认和复现最终版本。其中②是交互差异化重点，③决定“可交付”是否成立。真实频率和严重程度仍需目标用户任务测试。

3. 设计师从初稿到交付的旅程

主场景：设计师收到“成员邀请流程”的 PRD、旧稿和设计约束；AutoClaw 生成 Desktop/Mobile HTML 初稿。设计师发现 Mobile 无效邮箱提示离输入框过远，要求仅改这个状态，并确认 Desktop 和成功态不受影响，再与 PM 确认方向、评审 Demo、交给前端。

阶段 用户要判断 工作区的回应
接收与清点初稿 生成了哪些方向、页面、状态？缺什么？ 成果总览与覆盖清单。
草图收集 是否保留灵感、参考和反例？ 自由收集，暂不强行确认单一方向。
定义 1–3 个概念 哪个方向更有潜力？细节如何连续改善？ 方向并排、局部修订、保留演化历史。
G1 概念确认 核心路径、价值与原则是否成立？ PM 和设计师形成概念基线；高风险时开发提前预检。
Demo 体验评审 流程、异常态、响应式和实现边界是否可靠？ G2 在可运行版本上审阅并记录未解决问题。
开发接手 接收的是哪个版本？能否复现？ G3 固定交付快照：源码、资源、状态表、运行说明与已知问题。

后续的微调与上线验收在同一版本轨迹上继续，但不应静默覆盖已批准基线。采纳一次修改只是设计师把候选加入工作版；G1/G2/G3分别代表团队对概念、体验和接手的判断。

4. 核心 Feature：界面定域修订

统一链路：定位上下文 → 指出目标 → 定义意图与保留项 → 隔离生成候选 → 比较影响 → 人决定。

  • 文字微调适合明确文案。源文字可定位时直接改工作草稿，AI 只提供措辞建议和溢出检查。
  • 点选组件适合样式、布局和交互规则。系统预填方向、页面、状态、断点、基线版本及真实命中对象。
  • 画笔圈选适合表达一片视觉关系。它只提供视觉锚点；系统必须先显示识别到的 DOM/组件，映射不稳定时降低承诺或让用户重新选择。

三种入口都进入同一张修订卡。Agent 在隔离候选中修改源文件，保留原工作版；审阅页并排呈现原版与候选、源文件变动摘要和可能受影响的其他状态。设计师可采纳、继续限定或放弃。画笔圈住像素，不等于代码只改圈内。共享样式、组件复用和真实交互都要通过影响提示及回归检查处理。功能细节见 V07 功能定义。

5. 产品结构与 MVP 范围

项目 → 任务 → Design 工作区 → 方向/版本 → 页面 × 状态 × 设备。工作区导航以用户判断组织：成果总览、聚焦预览、修订审阅、交付快照；评审决定与版本记录贯穿其间。底层每份产物应有类型、来源、版本、负责人和关联对象。preview.version_id = delivery.version_id 是交付必须满足的约束。

P0：只处理 AutoClaw 自生成、源文件可用的 HTML 项目；索引页面/状态/断点；提供文字和元素定域修订、受限画笔、候选比较、采纳/放弃、固定版本交付。P1：对象锚定异步评论、1–3 方向并排、跨页面回归清单、约束模板和技术风险提醒。暂不承诺：任意外部站点原位修改、无限画布全功能、Figma↔HTML 无损同步、自动合并生产代码。

“可交付”指接收方能复现同一版本与状态，理解设计决策及未解决问题。HTML Demo 可能是可运行规格和工程起点；前端仍需核查组件体系、路由、真实数据、接口、权限、性能与无障碍。

6. 原型完成度与验证计划

可点击原型 V08 已呈现：AutoClaw 首页 → 成果总览 → 方向 B 预览 → 文字/智能/画笔修订 → 候选对比 → 设计师采纳 → PM 概念确认 → Demo 状态复核 → 固定交付页。它验证的是信息结构与交互顺序，尚未接入真实 AI、HTML 源文件改写或生产交付包。

建议先做一项真实 Auto Design HTML 任务走查，核对已有产物、修改、版本、导出能力，再用 5–8 位设计师、2–3 位前端进行发现性测试。重点记录：设计师能否在不重述整页需求的情况下连续完成两次微调；能否指出候选越界变化和当前正式版；PM 能否区分采纳修改与批准方案；前端能否独立复现交付包中的错误态。以上人数和指标是研究计划，并非已获得的结果。

研究依据与链接

  • AutoClaw Auto Design 官方介绍：公开描述聊天、评论/画布修改、多端预览与导出；仍需以实际客户端核对。
  • Lovart Advanced AI Editing：Quick Edit、Mark/Touch Edit 等官方说明；本稿的具体录屏观察另见 V03。
  • Canva AI Whiteboards：无限画布更适合发散和共同整理，不直接证明其应是本题 MVP。
  • Figma State of the Designer 2026：设计师调查，非 AutoClaw 用户样本。
  • Figma 2025 Designer and Developer Trends：设计与开发协作报告。
  • Chen 等，Rethinking the UI of GenUI：早期多方向 UI 探索研究，样本范围有限。
  • Wu 等，Improving UI Generation Models from Designer Feedback：位置化/直接修订反馈的研究；不作为本产品效果预测。
  • Figma Branching 指南、GitHub Copilot agents 文档：候选、审阅、接受的协作范式参考，不代表设计 UI 可直接照搬代码 PR。
