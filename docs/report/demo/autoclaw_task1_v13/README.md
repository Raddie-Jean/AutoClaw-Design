# 测试1 · 设计产物链路 V13

本任务参照用户提供的 WorkBuddy「Design工作区-可交互Demo.html」中的连续过程模式重新设计，沿用项目 AutoClaw V09/V10 规范和原始矢量图标。通过本地文件读取参考结构；原文件保持不变。

## 交付

- `index.html`：独立测试1交互 Demo。
- `designs.html`：14张关键过程画面的 SVG 总览。
- `screens/`：发起需求、澄清、生成、产物落地、预览、对象修改、候选、对比、版本、定稿、交付检查、完成、代码、图层。
- `figma-editable-import/` + `figma-plugin/`：配套原生文字导入。插件通过语法和数据校验，未在Figma实际运行验证。
- `delivery-example/`：从浏览器实际下载的定稿v2 SVG，输入卡片圆角为12。

## 操作路线

点击「发起示例任务」→确认规范并生成→查看预览→点选输入卡片→右侧将圆角25改为12→生成局部候选→对比工作版→采纳候选→版本中查看v1/v2→定稿→确认定稿→导出→下载SVG与manifest。

首页标题可改文字，侧栏可改背景颜色，账户工具栏可改文字颜色。历史版本只读；候选采纳前不覆盖工作版；定稿复制为独立快照。代码、画布和下载来自同一SVG内容。导出检查实际解析SVG尺寸、文字数量、字体声明和位图元素，不采用硬编码的成功报告。

生成进度与自然语言处理为本地模拟，仅示例属性修改真实执行。图标来自本机AutoClaw资源；基准稿中原有位图已替换为矢量示意头像、金币与原生图标。这不是官方设计系统或真实Agent服务。

## 与测试2的边界

测试1包含设计生成、对象编辑、版本与定稿交付。没有邀请、评论、协作处理入口。测试2通过另一个任务页面进入，各自维护状态，统一演示入口只负责选择和切换路径。

## Figma调整后如何进入演示

1. 将`screen`目录内所需SVG导入Figma；需要原生文字时使用配套JSON导入工具。
2. 完成调整后，导出SVG，保留对应文件名，替换`screens/`中的该状态设计稿。
3. 刷新设计稿总览，页面会读取替换后的SVG。统一演示顶部「查看本路径SVG」进入此总览。
4. 交互Demo由HTML实现；修改静态SVG不会自动改动HTML组件和状态逻辑。设计确定后，再按最终SVG同步对应交互界面。此轮保留设计稿与交互Demo并行，方便逐步确认。

SVG不含Figma组件实例、自动布局和原型连线。标准SVG文字是否可直接编辑取决于导入方式。配套插件的文字坐标可能受本机字体影响，需要少量调整。
