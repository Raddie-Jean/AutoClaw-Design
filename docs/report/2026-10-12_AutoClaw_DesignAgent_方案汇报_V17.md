# AutoClaw Design Agent｜方案汇报 V17

本版依据测试题、用户提供的产品截图与录屏截帧、本地研究和最新 V13 双任务设计稿整理。汇报集中说明四件事：如何与 AI 协作确定方向；从竞品画面中观察到什么；两项测试任务如何落到信息架构与交互原型；设计稿如何从 AutoClaw 基础界面发展到可演示、可检查的状态。未进入最终设计的“草图三态”等探索不占独立汇报页面。

## 01｜题目与最终范围

测试题的 Task 1 要求 Design 任务完成后，用户能够查看、预览、编辑和管理 HTML 设计产物。方案将入口放在 Agent 的任务结果卡：设计师打开产物工作区，识别主稿、派生预览和输入参考；进入预览后对具体对象进行局部修订，在候选审阅后固定交付版本。Task 2 选择“版本锚定的协作建议”作为单一深入 Feature：PM 或前端针对某一版本的页面和对象提出建议，设计师决定是否转为修改候选。Task 2 不依赖实时多人编辑，也不是 Task 1 的前置条件。

当前最新交互稿 V13 使用 SVG 作为可实际修改、检查和导出的单一示例产物，并以 HTML 页面承载原型交互。它验证了该样例中的设计链路，**尚未证明任意 HTML/CSS/JS 项目都能被同样精确地编辑与回写**。本汇报将题目目标与原型已验证范围分开陈述。

## 02｜创意发散与 AI 协作

早期探索覆盖 AI 设计工具、无限画布、多格式产物和设计开发交接。AI 用于收集和归类工具模式、把零散问题整理为用户旅程与信息架构、快速生成 HTML/SVG 可检验稿；设计师持续校正问题范围、功能优先级和产品结构。能够在文件中核对的阶段产出包括：[研究方向 V01](../process/md/2026-09-29_AI-Design-Agent_研究与方案方向_V01.md)、[MVP 观察 V03](../process/mvp_v03/2026-10-04_AutoClaw_Design工作区_MVP初稿_V03.md)、[双任务信息架构 V13](../process/design_workspace_v13/2026-10-12_AutoClaw_Design测试题_双任务信息架构_V13.md)、[测试 1 最新原型 V13](demo/autoclaw_task1_v13/index.html) 和 [测试 2 最新原型 V13](demo/autoclaw_task2_v13/index.html)。

方向演进中的关键调整：最初尝试用大画布承接所有格式；在确认题目现有主产物为 HTML 后，改以可运行项目为主稿；在原型评审中发现“独立 Design App 套壳”的结构偏离 AutoClaw 操作流程，于是将工作区放回任务结果右侧；最后将单人产物闭环和未来协作 Feature 分开。这些是本项目的方案变更记录，不是对目标用户痛点频率的统计结论。

## 03｜截图研究：三种生成后工作方式

**Lovart。**用户录屏的截帧可见：对象选中后出现上下文工具；Quick Edit 输入框与选中对象相连；新生成结果与原稿并置。可借鉴的是“定位对象—下达局部指令—保留候选”的顺序。该素材对象属于视觉画布，不能据此推断 HTML 代码能稳定映射到圈选区域。[逐帧观察](../process/mvp_v03/2026-10-04_AutoClaw_Design工作区_MVP初稿_V03.md)。

**万相。**用户提供的截图显示左侧指令与生成过程、右侧多节点画布，画布工具可添加图片、视频、文案、画布、图形和画笔。这个结构适合组织多模态结果，但网页交互的主稿仍需运行预览，静态画布不能替代 HTML 编辑与状态验证。截图见本目录 `assets/wanxiang-canvas.png`。

**WorkBuddy。**用户提供的截图显示项目/任务列表、对话内文件卡和右侧画布并存；另一个画面将研究文档与分享面板放在任务旁边。可借鉴任务与成果并列的工作区结构。当前截图没有展示足够的 HTML 精准编辑控件，不能将其归入已验证能力。截图见 `assets/workbuddy-canvas.png` 和 `assets/workbuddy-delivery.png`。

用户的 [Figma 竞品调研画板](https://www.figma.com/design/XytIsXg4S2lL45NriFX69i/%E6%99%BA%E8%B0%B1%E6%B5%8B%E8%AF%95%E9%A2%98-2026?node-id=246-2661) 还包含扣子等补充材料。当前 Figma 接口触发 Starter 调用额度限制，本版未能逐张读取该节点，因而只对本地可核对截图做具体功能判断。

## 04｜产品决策与信息架构

四项决定构成方案边界：第一，沿用 AutoClaw 项目、任务、对话的基本结构，任务完成卡是工作区入口；第二，题目中的 HTML/CSS/JS 与引用资源应作为可运行主稿，截图、PRD、Figma 链接与导出图片是关联资料，V13 暂以 SVG 样例验证同源编辑；第三，轻量画板用于整理与比较，具体修改进入预览并锚定实际对象；第四，AI 修改先形成隔离候选，由设计师比较并采纳，交付文件与预览保持同一版本。

层级为 `项目 → Design 任务 → 产物集 → 主稿/参考/派生文件 → 页面×状态×设备×版本 → 对象 → 候选 → 工作版 → 交付快照`。页面布局延续 AutoClaw 左侧项目与任务、中间对话，新增右侧产物工作区。工作区依任务切换“成果、预览与编辑、版本与交付”；Task 2 的建议绑定具体版本与对象，并回流到候选审阅。完整结构见 [V13 信息架构](../process/design_workspace_v13/2026-10-12_AutoClaw_Design测试题_双任务信息架构_V13.md)。

## 05｜Task 1 核心交互

目标链路为 `Agent 任务 → 澄清约束 → 产物落地 → 预览和定位对象 → 输入确定属性/补充指令 → 生成隔离候选 → 对比和采纳 → 定稿 → 检查并导出`。V13 将它放在 AutoClaw 任务结构内：左侧保留项目与任务，中间保留与 Agent 的连续对话，右侧依阶段呈现画布、代码、图层和版本。

最新原型通过一个具体修改检验链路：用户先确认 1512×945 画板、样式、矢量和文字要求；Agent 生成首版 SVG；用户点选“输入卡片”，把圆角从 25px 输入为 12px；候选 v2 与工作版 v1 并排比较；设计师采纳后 v2 成为工作版，v1 留在历史；定稿检查实际 SVG 尺寸、文字元素、字体声明和位图元素，下载定稿 SVG 与 manifest。自然语言处理和生成进度是本地模拟；该示例中的属性修改、候选、版本和导出是可操作的。对应画面：[确认规范](demo/autoclaw_task1_v13/previews/02_澄清与确认规范.png)、[产物落地](demo/autoclaw_task1_v13/previews/04_产物落地.png)、[对象修改](demo/autoclaw_task1_v13/previews/06_选中对象与属性修改.png)、[候选比较](demo/autoclaw_task1_v13/previews/08_候选与工作版对比.png)、[交付检查](demo/autoclaw_task1_v13/previews/11_交付检查_实际SVG结构.png)。

这一示例说明了“当前可编辑源文件—预览—局部候选—定稿导出”怎样共用一个版本。要回到测试题的 HTML 主产物，还必须验证选区到 DOM/组件的映射、样式回写、跨页面与响应式状态检查、资源依赖和打包复现；这些能力不以 SVG 样例替代。

## 06｜Task 2 与过程评审

Task 2 的最新 V13 原型被拆为[独立的版本协作评审任务](demo/autoclaw_task2_v13/index.html)，从已有首页 v1 开始，不包含 Task 1 的需求生成或定稿交付。建议记录 `version_id + view_id + target_ref`；产品经理和前端对固定版本、页面状态与对象提出建议，设计师决定是否创建候选、采纳或暂不处理。历史建议停留在原版本，处理结果进入[评审记录](demo/autoclaw_task2_v13/previews/03_独立评审记录.png)，可下载本地 JSON。截图还包括[独立评审任务](demo/autoclaw_task2_v13/previews/01_独立协作评审任务.png)和[协作候选审阅](demo/autoclaw_task2_v13/previews/02_协作候选审阅.png)。

原型展示的是定域建议及设计师采纳/保留的决定。邀请与反馈不发送到外部服务，刷新会重置本地状态。此前讨论过的 PM 概念评审、开发技术预检与实时共同编辑尚未形成经验证的完整流程，本版不把这些口头设想写成既有产品机制。

## 07｜界面还原、规范与设计稿产出

原型先从用户提供的 AutoClaw 首页和任务界面提取布局与视觉基线，再在同一壳层内扩展右侧产物工作区。本地 [统一界面 V08](../process/autoclaw_unified_v08/README.md) 和 [可视化设计规范 V10](design-spec/README.md) 给出布局、颜色、文字、组件、图标与交付规则。参考画板 1512×945；任务加预览布局为 280 侧栏 / 420 对话 / 812 预览。规范是本项目执行值，新增组件不代表 AutoClaw 官方现有组件。

设计稿经历三次可见调整：先还原 AutoClaw 基础界面与图标；再依据用户指出的“套壳、不符合 Agent 任务流程”问题，将产物入口接回任务对话；最后拆出测试 1 与测试 2 的独立链路。最新 [V13 测试 1 文件包](demo/autoclaw_task1_v13/README.md) 有 14 张关键状态 SVG、独立 HTML 原型、预览图、Figma 导入辅助文件和浏览器实际下载的 SVG 交付样例；[V13 测试 2 文件包](demo/autoclaw_task2_v13/README.md) 有 4 张评审状态 SVG 和独立交互原型。AI 参与界面整理、SVG/HTML 制作和重复状态生成；产品结构、功能取舍和评审反馈由设计师给出。Figma 导入插件已做语法和输入校验，尚未在 Figma 实际运行验证文字与组件保真度。
