# AutoClaw 基础设计规范 V09

版本：2026-10-12 · 适用：本项目后续 AutoClaw 界面、原型与 SVG 设计稿。

## 1. 规范地位与依据

这是一套已经用于本项目还原稿的**执行基线**，后续设计默认沿用。它不是 AutoClaw 官方发布的设计系统。

参考优先级：用户最新指定的 Figma 基准稿 → 本规范的已确认参数 → 本规范的当前执行值 → 新场景的扩展建议。遇到冲突先查基准和现有文件，不能凭记忆替换图标或改变布局。

|---|---|---|

|V08 两张统一规范界面 SVG|当前颜色、字体、圆角、阴影的可复用实现|已渲染检查，是本规范当前执行值|

## 2. 视觉方向

浅灰侧栏、白色工作区、大面积留白；灰阶负责层级，少量蓝色负责链接和技能状态，橙色负责购买。界面以工作内容为中心，减少装饰。悬浮输入框允许柔和阴影，普通列表与工具栏主要依靠底色、间距和细分割线区分。

默认保持浅色主题。不自行增加渐变背景、玻璃效果、大面积品牌色、夸张投影或一套新的图标风格。未来新功能改变内容与组件组合，优先保持已有壳层和组件外观。

所有数值为设计逻辑像素。截图原始 3024×1890 对应 1512×945 设计画板；不要把截图物理像素直接作为字体和控件尺寸。

首页内容按工作区居中，不按整张画板居中。聊天、代码、文件树各自有内容滚动区域；固定栏不跟随正文滚动。底部输入框和免责声明保持可见，不覆盖最后一条消息。

**扩展建议**：新画板宽度变化时侧栏保留 280，首页内容最大宽 768、左右最少留 24；空间不足时优先收起文件树，再收起侧栏。具体断点需按目标画板验证，不凭此文档推断官方响应规则。预览工具中的“手机/平板/桌面”只改变嵌入网页预览尺寸，不改变应用外壳。

## 4. 色彩

以下均为**当前执行值**。新增颜色须有明确语义，不将购买橙色泛化为所有主按钮颜色。

|次要文字/图标|#666666、#777777|辅助标签、工具图标|
|弱提示|#999999 / #A3A3A3|输入占位、过程说明；不用于关键正文|

## 5. 字体与文本

当前执行字体：中文及普通界面使用 **PingFang SC**，代码使用 **Menlo**。跨平台回退可用 Microsoft YaHei / Arial，但需重新检查文字宽度和换行。

|文本角色|字号/字重|推荐行高|依据|
|---|---|---|---|
|首页欢迎标题|26 / Regular 400|36|字号执行，行高建议|
|任务标题|16 / Semibold 600|22|执行|
|菜单、正文、输入控件|14 / Regular 400|20；多行正文可用 24|字号与主要行高确认/执行|
|工具栏、文件名、分组标题|13 / Regular 400|18|执行|
|代码|12 / Regular 400|24|执行|
|免责声明、次级说明|11–12 / Regular 400|16–17|执行|
|快捷键、角标|10–11 / Regular 400|14–15|执行|

中文不人为拉大字距。图标与文字之间优先使用 8px；长文件名与任务名按容器截断，完整内容应可被查看。示意稿需要准确保留业务文案，不为排版美观删改关键含义。

## 6. 间距、圆角、边框与阴影

通用间距采用 **4 / 8 / 12 / 16 / 24 / 32 / 40 / 48**。已有组件有 10、14、18、25 等原稿特例，应保留，不为强制整齐而改变。

|组件|圆角执行值|
|---|---|
|白色工作区外轮廓|16|
|侧栏行、文件选中行|8–9|
|工具栏轻按钮/菜单|9–12|
|场景切换条/内层选项|13 / 12|
|任务操作结果卡片|13|
|用户消息气泡|19|
|输入框|25|
|32×32 圆形动作按钮|16|

细边框默认 0.7px、#E9E9E9；Figma 基准中存在 0.8px/1px 元素，不将所有线条机械改成同一个宽度。图标描边属于图标自身资源，不跟随卡片边框参数。

输入框柔和投影当前为：x=0、y=10、blur 约 40、spread=0、#1F1F1F、5.5%。SVG 实现是 `stdDeviation=20`，与 Figma blur 为近似换算，需视觉核对。仅悬浮输入框/浮层使用；普通列表行不用阴影。

## 7. 组件约定

### 侧栏导航

侧栏水平内边距 10；新建任务行 260×34、圆角 8。任务/智能体切换为轻灰胶囊选中态。常规导航图标槽 20×20；列表任务区沿用 32px 左右行距，文字左边界 x=18。底部账户区固定，保留头像、用户标识、方案名和倍率徽标。

### 首页场景切换

四个场景并列，容器 439×40，选中项白底。图标与文字垂直居中。原生办公、代码、法律图标为小尺寸 PNG：保持原图，不自动描边冒充精确 SVG；需要全矢量版本时单独标注替代来源。

### 输入框与项目条

输入框为主要悬浮组件；占位文字距左 16、文字基线距顶约 34。左下依次为添加、默认权限、Agent 集群；右下为模型/模式选择和发送。功能分组与顺序保持不变。首页项目条位于输入框后方，左右各缩进 16，不做成另一个独立悬浮大卡片。

空输入：发送按钮浅灰，向上箭头白色；可发送：深色圆按钮；执行中：深色圆按钮内白色停止方块。可发送状态为扩展建议，执行中状态来自截图。状态转换不改变按钮位置和外径。

### 对话、工具结果与附件

助手内容左对齐，不增加包围全部正文的大卡片。用户消息右对齐、浅灰气泡。思考耗时、读取/命令数量使用弱灰文字。已编辑文件结果使用白底细边框卡片，增删统计对齐右侧。附件与文件链接沿用代码图标和蓝色标识，不使用随机文件图标替换。

### 标签、代码与项目文件树

顶部标签是浅灰小胶囊，含文件图标与截断文件名；右侧保留添加、展开、关闭。第二行保留当前文件名、打开、导出、项目文件按钮。代码区独立行号栏，等宽字体；文件树单独分栏，用缩进与折角表示层级，选中行浅灰。语法色只用于代码，不混入一般正文层级。

### 菜单与新状态

设备菜单沿用白底圆角容器、单列条目、右侧勾选，不引入新的选择样式。Hover 可用轻灰底、Focus 可用 2px 蓝色边框、Pressed 可加深一档；这三类为**新增交互建议**，不是从静态截图确认的状态。后续交互稿应补齐 default / hover / focus / selected / disabled / loading 中适用的状态。

## 8. 图标规范与素材索引

优先级：基准稿中的同款图标 → V06 本机原始矢量 → V07 明确标注的补充图标 → 经说明的替代/重绘。不能根据名称相近就替换，也不能把同一库的全部图标统一加粗。

|用途|推荐素材|说明|
|---|---|---|
|任务/智能体/侧栏/视图/搜索|V06 自定义 task、agent、sidebar、view、search|导航槽 20px；保留原生 viewBox|
|Skill、新增项目、编辑|V06 自定义 skills、folder-add、edit|图标与基准同款|
|Agent 集群|V06 自定义 cluster|常用槽 17px|
|默认权限|V07 01_默认权限_盾牌勾.svg|常用槽 15–17px|
|任务列表圆点横线|V07 02_任务列表_圆点横线.svg|几何重绘，不是上下错位的 sliders|
|导出|V07 03_导出_向下箭头.svg / V06 custom-063-gtn|保留原始路径|
|加号|V06 内置 Lucide plus|不要误用带圆圈的 new-task|
|代码标识、两角展开|V04 file-code、fullscreen / 以基准实际图形为准|V04 是截图几何重绘；与原生版本不同，需按槽匹配|

图标外框与可见路径边界不同，先按原始 viewBox 等比缩放，再看视觉中心。单色界面图标用 #666 / #777，强调态按语义用蓝色。所有 SVG 固定颜色，保留 `fill="none"`、fill-rule、clip-rule、stroke-linecap、stroke-linejoin；缺少根节点 fill="none" 会将线性图标错误填实。

原生扩展描边路径属于填充型矢量，只能编辑路径；Lucide 属于真实 stroke，可调整描边。两者都可缩放，但不能用同一种方式改粗细。不得用截图轮廓提取版作为新稿默认素材。头像、金币、品牌和摄影素材允许位图，交付时列明。

## 9. Figma 与 SVG 交付

Figma 新稿建议按 `App / Sidebar / Toolbar / Content / Composer / Preview / FileTree` 分层，复用导航行、图标按钮、输入框、消息、文件卡片、菜单等组件。优先给组件定义状态和文本属性；创建真实组件与自动布局是后续制作要求，现有 SVG 不自带这些语义。

SVG 必须包含完整 viewBox、固定画板尺寸、命名分组、独立图标路径及 `<text>` 文本。不要将主界面整张截图嵌入后称为可编辑稿；不要引用临时远程资源。保留透明度、裁剪和内外层顺序，检查跨图标 ID 冲突。

**文字编辑边界**：SVG 源文件的 text 可以编辑，但 Figma 导入可能转轮廓。需要 Figma 原生文字时使用 V08 本地导入插件或直接创建 Text 图层。该插件只通过语法检查，尚未实测 Figma 运行；使用后必须检查字体和基线。不能把 SVG 导入结果称为保留了官方组件实例。

## 10. 后续设计的默认工作流程

1. 先读取本规范和当前基准，确认设计画板及页面类型。
2. 复用对应外壳；只替换业务内容与必要区域。新页面先选首页、对话+预览、对话+代码三种布局之一。
3. 复用已标明的组件与图标，使用随附 tokens.json 中的语义参数，不临时猜测颜色和线宽。
4. 为新功能补齐必要状态。推荐值与原稿确认值分别记录；重要变化由用户决定。
5. 渲染实际输出，按基准检查比例、文字、图标、对齐、层级和状态；修复后再打包。
6. 交付最终文件、预览、素材来源和未验证项；旧版不覆盖。规范调整另起版本，并写变更摘要。

### 每次交付检查

- 画板比例与逻辑像素正确；工作区按自身居中，侧栏和分栏宽度符合对应布局。
- 字体无缺字；正文未挤压；多行文本和文件名无溢出、错误换行。
- 图标与使用槽同款；加号、带圈加号、滑杆、任务列表等没有混用。
- 图标无毛边、错误填实、缺失路径、外部CSS依赖或空白渲染。
- 留白、灰阶、选中态与组件圆角保持一致，投影不过重。
- 主界面没有被整体栅格化；位图清单准确；Figma文字可编辑性实际核验后再声明。
- 文件名、版本、来源、检查记录完整；新扩展与已确认值明确区分。
